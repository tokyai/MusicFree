# 横屏响应式布局优化

## Goal

让 MusicFree 在横屏时充分利用宽度，把原本上下排列且互相挤压的主要内容改为可扫描、可独立滚动的左右布局，同时保持竖屏体验、播放行为、插件查询和其他业务逻辑不变。

## Background

-   项目已经通过 `src/hooks/useOrientation.ts` 集中监听方向变化，但只有主页、播放详情、歌手详情和关于页存在局部横屏分支。
-   `rpx()` 按窗口短边缩放。页面级 `width: rpx(750)` 在横屏时只等于屏幕高度，不能代表可用宽度，现有歌手页、下载页、榜单页等因此出现留白或挤压。
-   主要页面由顶部 `AppBar`、中间内容和底部 `MusicBar` 组成；这两个固定区域应继续保持在顶部和底部。
-   Android 工程的 `minSdkVersion` 是 24，因此本任务的 Android 验证基线是 Android 7.0 / API 24 及以上，不承诺 Android 6。

## Requirements

### R1. Shared responsive contract

-   继续使用现有集中式方向状态，不在列表项中增加独立的 Dimensions 监听器。
-   横屏主次内容默认采用接近 `38:62` 的左右比例；播放详情采用 `50:50`。
-   顶部应用栏保持在顶部，存在迷你播放器的页面继续把迷你播放器固定在底部。
-   页面内容使用实际可用宽度和 flex 约束；只把 `rpx()` 用于控件尺寸、间距和字体，不再把 `rpx(750)` 当作横屏整页宽度。
-   左右安全区、状态栏、导航栏和键盘出现时不得遮挡可操作内容。

### R2. Existing landscape pages

-   主页横屏为左侧快捷操作、右侧歌单，比例和滚动行为统一到共享响应式规则。
-   播放详情横屏保持左侧封面与控制、右侧歌词，固定为 `50:50`，歌词和控制不得互相遮挡。
-   歌手详情横屏为左侧歌手资料、右侧单曲/专辑结果，双方独立滚动。
-   关于页横屏为左侧作者资料、右侧正文，避免固定短边宽度造成空白或裁切。

### R3. Sheet, album, and ranking details

-   本地歌单、插件歌单、专辑和榜单详情在横屏时统一为左侧元数据、右侧有序歌曲列表。
-   左侧封面、标题、数量和描述可独立滚动；播放全部、收藏、添加等主要操作固定在左侧操作区，不随描述滚出视口。
-   右侧歌曲列表独立滚动并保留加载更多、重试、高亮当前歌曲和点击播放语义。
-   竖屏继续使用当前“元数据作为列表头部”的单列结构。

### R4. Rankings, recommendations, and global search

-   横屏时把榜单来源、推荐来源与标签、搜索媒体类型与音源选择放入左侧纵向筛选栏，结果区放在右侧。
-   筛选栏在项目很多时可独立滚动，并明确显示当前选项。
-   竖屏继续使用现有横向 TabBar、标签条和滑动分页交互。
-   切换筛选项不得改变已有请求、分页、重试和空状态语义。

### R5. Settings

-   设置页横屏采用左侧目录/分类、右侧设置内容的结构；主题、备份、关于及插件子页按各自内容边界使用同一规则。
-   基本设置左侧目录和右侧 `SectionList` 双向同步：点目录滚到对应分组，手动滚动内容时目录高亮跟随当前分组。
-   插件列表、排序、订阅等子页在横屏时保留顶部导航和现有安装、排序、编辑、分享行为。
-   竖屏设置结构和现有导航路径不变。

### R6. Ordered lists

-   本地音乐、历史记录、下载列表、列表内搜索以及其他单歌曲列表保持一个有序列表，不改为网格。
-   横屏歌曲行改为表格式列布局，优先稳定展示序号、标题、歌手、专辑、来源和操作；窄横屏可按优先级隐藏次要列，但不得挤压标题和操作按钮。
-   歌曲顺序、点击播放、长按、更多菜单、当前歌曲高亮和虚拟列表行为保持不变。

### R7. Editors and utility pages

-   歌曲列表编辑器和文件选择器横屏时主列表在左，选择、保存、批量操作或确认操作组成常驻右侧纵向操作栏。
-   自定义主题横屏时预览在左、控制项在右；权限页和其他明显上下分区的工具页按主次关系改为左右布局。
-   旋转、返回、文件夹层级切换、选择状态和软键盘显示不得导致操作区覆盖内容。

### R8. Drawer and overlays

-   主页抽屉在横屏时使用适合宽屏的受限宽度，内容仍可完整滚动。
-   普通面板在横屏时从右侧滑入；竖屏仍从底部或既有位置滑入。
-   模态对话框在横竖屏均保持居中，并在横屏限制宽高以避免按钮或正文被裁切。
-   全屏面板继续全屏，不改为分栏或侧栏。
-   Android 返回键、点击遮罩关闭、动画结束卸载和键盘避让行为保持不变。

### R9. Compatibility and behavior boundaries

-   共享 React Native 布局同时适用于 Android 和 iOS，不引入平台专用业务分支。
-   不修改播放器、B 站识曲、歌词、插件、下载、备份、权限请求或音源查询逻辑。
-   不增加持久化布局设置；方向变化只影响当前渲染布局。
-   不主动重构与横屏无关的旧代码。

## Out of Scope

-   横竖屏方向锁定、平板专属导航体系、桌面端布局和可自由拖动分栏。
-   新增播放器功能、音源能力、导入协议、评论或业务数据字段。
-   重做视觉主题、图标体系、字体缩放策略或全局导航架构。
-   支持 Android 6 / API 23 及更低版本。

## Acceptance Criteria

-   [ ] AC1: 19 个现有顶层路由逐一审计；所有具有明确主次上下分区的页面均有对应横屏左右布局，纯有序列表页保持单列表。
-   [ ] AC2: 播放详情横屏为 `50:50`；其他主次页面默认接近 `38:62`，顶部 AppBar 和底部 MusicBar 不参与左右分栏。
-   [ ] AC3: 本地歌单、插件歌单、专辑和榜单详情的左右区域可独立滚动，左侧主要操作始终可见，右侧列表可正常分页和播放。
-   [ ] AC4: 榜单、推荐和搜索的来源、媒体类型或标签在横屏进入左侧纵向筛选栏，当前选项、空状态、重试和分页均正确。
-   [ ] AC5: 基本设置目录点击和内容滚动能够双向同步；其他设置及插件子页无裁切、无重叠。
-   [ ] AC6: 横屏歌曲列表保持原顺序并呈现稳定列；标题和操作按钮在受支持的最窄横屏视口仍可使用。
-   [ ] AC7: 编辑器和文件选择器的右侧操作栏常驻，选择、保存、删除、批量操作和确认行为与竖屏一致。
-   [ ] AC8: 普通面板横屏从右侧进入、对话框居中、全屏面板仍全屏；返回键、遮罩关闭和键盘避让通过验证。
-   [ ] AC9: 旋转过程中无崩溃、明显闪白、互相覆盖或不可恢复的空白；播放不中断，页面请求和选择状态不被业务层重置。
-   [ ] AC10: 竖屏页面没有有意的结构或交互回归，播放、插件查询、歌词、下载和备份相关测试继续通过。
-   [ ] AC11: TypeScript、Jest、ESLint 零错误，Android debug 构建通过；ESLint 既有警告单独记录而不扩散。
-   [ ] AC12: 至少在 API 24+ Android 的窄横屏和常规横屏完成旋转、列表、面板、对话框、键盘和安全区人工验证；iOS 在可用模拟器上验证共享布局。
