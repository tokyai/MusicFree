# 完善搜索、详情导航与收藏批量换源

## Goal

完善歌曲发现与收藏可用性：搜索结果可以快速辨认封面，播放详情可从歌手
和专辑继续查找作品，收藏歌曲可批量迁移到另一个仍可播放的音源。

## Scope

本父任务由三个可独立验收的子任务组成：

1. `08-17-search-result-covers`：搜索歌曲行展示封面缩略图。
2. `08-17-player-metadata-search-navigation`：播放详情的歌手/专辑跳转搜索。
3. `08-17-favorite-batch-source-switch`：收藏歌曲勾选、全选及指定音源替换。

## Requirements

- 歌曲搜索结果在横屏表格和普通列表中展示稳定尺寸的封面；缺图或加载失败
  时使用现有默认专辑图。
- 播放详情的歌曲选项面板中，点击歌手或专辑都进入搜索页的“单曲”结果，
  分别以歌手名或专辑名作为关键词自动执行搜索。
- 收藏歌单菜单提供批量换源入口，复用现有批量勾选和全选能力。
- 用户为所选歌曲指定一个已启用且支持单曲搜索的插件；系统匹配并验证目标
  歌曲可播放后，才允许替换收藏记录。
- 跨平台匹配不得比较歌曲 ID；原曲、现场版、Remix、伴奏、翻唱等版本语义
  必须一致，无法确认同一录音版本时保留原收藏。
- 替换不得打乱歌单顺序，不得制造重复收藏，不影响未选中歌曲。
- 正常完成时一次性保存全部成功项，匹配或验证失败项保留原记录并汇总提示；
  用户主动取消时整批不保存。
- 手机、普通横屏和车机横屏均需保持文字、封面和操作区可用。

## Acceptance Criteria

- [ ] 有封面、无封面和封面请求失败的搜索歌曲均有正确且不抖动的预览图。
- [ ] 歌手和专辑点击后均打开单曲搜索，关键词正确且结果可以继续翻页。
- [ ] 收藏页面可以勾选单首、多首或全选，并选择目标音源执行换源。
- [ ] 只有通过身份匹配及播放能力验证的歌曲会被替换。
- [ ] 换源后重新进入收藏页仍使用新音源，顺序和未选中歌曲保持不变。
- [ ] 部分失败、取消、目标源不可用和重复结果都有明确且可恢复的行为。
- [ ] TypeScript、Jest、ESLint 和 Android 构建通过，并完成代表性横竖屏验证。

## Out Of Scope

- 不修改或重新发布 `1.js` 至 `9.js` 音源脚本。
- 不自动迁移所有歌单，也不在后台无提示地更改收藏来源。
- 不新增导入、导出或评论功能。
